Objetivos de Aprendizaje

Al finalizar este módulo podrás: Comprender cómo funciona el Sistema de Nombres de Dominio (DNS) y su papel crucial en Internet.
Dominar: Resolución de nombres, jerarquía DNS, tipos de registros y herramientas de consulta.

3.1 El Problema de la Memoria

¿Por qué no usamos números directamente?

Imagina que para llamar a tu mejor amigo tuvieras que memorizar el número 192.168.1.147 en lugar de simplemente buscar "Juan" en tu agenda. Esto es exactamente lo que pasaría en Internet sin DNS. Las computadoras usan direcciones IP numéricas (como 172.217.14.238) para comunicarse, pero los humanos necesitamos algo más fácil de recordar como google.com.
Analogía con tu teléfono:
Tu contacto "Mamá" en realidad apunta al número +52-55-1234-5678. DNS funciona igual: "google.com" apunta a 172.217.14.238.

Nombres vs direcciones: la solución humana

El DNS (Domain Name System) actúa como una guía telefónica gigante y distribuida que traduce nombres amigables para humanos en direcciones IP que entienden las máquinas. Esta traducción se llama resolución de nombres y sucede cada vez que escribes una URL en tu navegador.

El sistema de nombres jerárquico

DNS usa una estructura de árbol invertido, donde cada nivel tiene autoridad sobre los niveles inferiores. Esto permite que nadie tenga que mantener una lista completa de todos los nombres en Internet.
. (raíz) ├── com │ ├── google │ │ ├── www │ │ └── mail │ └── facebook ├── org │ └── wikipedia └── mx └── gob

3.2 La Jerarquía Global

Raíz: los jefes supremos del Internet

En la cima del sistema DNS están los servidores raíz, solo 13 en todo el mundo (nombrados de la A a la M). Estos "jefes supremos" conocen dónde encontrar información sobre todos los dominios de nivel superior como .com, .org, .mx, etc.

Dominios de nivel superior: .com, .org, .mx

Los TLD (Top Level Domains) son como los "jefes regionales". Por ejemplo, .com maneja todos los dominios comerciales, .mx maneja dominios mexicanos, y .edu maneja instituciones educativas. Cada TLD tiene sus propios servidores autoritativos.
Ejemplos comunes:
gTLD (genéricos): .com, .org, .net, .info
ccTLD (países): .mx (México), .es (España), .uk (Reino Unido)

Dominios autoritativos: quien tiene la respuesta final

Los servidores autoritativos son los que tienen la información definitiva sobre un dominio específico. Cuando registras "miempresa.com", designas qué servidores serán autoritativos para ese dominio y todos sus subdominios.

3.3 El Viaje de una Consulta

"Walking the tree": siguiendo la cadena de preguntas

Cuando escribes "www.google.com" en tu navegador, se inicia una cadena de preguntas que "camina por el árbol" DNS:

1. Tu computadora pregunta al servidor DNS local: "¿Dónde está www.google.com?"
2. Si no lo sabe, pregunta a un servidor raíz: "¿Quién maneja .com?"
3. El servidor .com responde: "¿Quién maneja google.com?"
4. Finalmente obtiene la dirección IP de www.google.com

Caché: recordar respuestas para ser más rápido

Para evitar hacer este viaje completo cada vez, los servidores DNS cachean (guardan temporalmente) las respuestas. Es como si tu cerebro recordara que "google.com = 172.217.14.238" por un tiempo determinado.

TTL: cuánto tiempo recordar una respuesta

El TTL (Time To Live) especifica cuánto tiempo puede un servidor mantener una respuesta en caché antes de preguntar de nuevo. Un TTL de 3600 segundos significa "recuerda esta respuesta por 1 hora".
TTL en la práctica:
TTL bajo (300s) = Cambios rápidos, más tráfico DNS
TTL alto (86400s) = Menos tráfico, cambios más lentos

3.4 Tipos de Registros

Los diferentes tipos de información DNS

DNS no solo traduce nombres a direcciones IP. Puede almacenar diferentes tipos de información usando registros DNS:

Registro A: dirección IPv4

El registro más común. Mapea un nombre a una dirección IPv4.
Ejemplo: www.ejemplo.com → 192.168.1.100

Registro AAAA: dirección IPv6

Como el registro A, pero para direcciones IPv6 (128 bits).
Ejemplo: www.ejemplo.com → 2001:db8::1

Registro CNAME: alias o apodo

Crea un "apodo" o alias para otro nombre de dominio.
Ejemplo: ftp.ejemplo.com → servidor.ejemplo.com

Registro MX: para correo electrónico

Especifica qué servidor maneja el correo electrónico para un dominio.
Ejemplo: ejemplo.com → mail.ejemplo.com (prioridad 10)

Registro TXT: información extra

Almacena texto arbitrario, usado para verificaciones, políticas de seguridad, etc.
Ejemplo: ejemplo.com → "v=spf1 include:_spf.google.com ~all"

3.5 Gestión de Dominios

¿Qué pasa cuando registras un dominio?

Cuando registras un dominio, estás esencialmente "alquilando" ese nombre por un período específico. El registrar actualiza la base de datos del TLD correspondiente para incluir tu dominio y los servidores DNS que especifiques.

Propagación: esperar que todos se enteren

Cuando cambias la configuración DNS, la información nueva debe propagarse por toda la red mundial de servidores DNS. Este proceso puede tomar de minutos a 48 horas, dependiendo de los TTL configurados.

Problemas comunes y soluciones

Problema: "No puedo acceder a mi sitio web después de cambiar DNS"
Solución: Verificar propagación, limpiar caché DNS local, verificar TTL

Problema: "Mi correo no funciona"
Solución: Revisar registros MX, verificar prioridades
Herramientas útiles:
nslookup - Consultas DNS básicas
dig - Consultas DNS avanzadas
whatsmydns.net - Verificar propagación global
