Cómo funciona
Internet

Antes de hablar de nube, servidores o AWS — necesitas entender qué pasa cuando alguien escribe una URL en el navegador. Este módulo te da ese modelo mental.

~45 min 2 actividades Quiz final 100 XP
1 ¿Por qué necesitas esto antes de AWS?

AWS, Azure, Google Cloud — todos son servicios que corren sobre infraestructura de internet. Si no entiendes cómo funciona internet, usar la nube se convierte en copiar comandos sin entender qué hacen.


Con este módulo vas a construir el modelo mental que te falta: qué pasa entre que escribes google.com y aparece la página. Ese proceso de milisegundos es la base de todo lo que viene.

Dato clave: Cuando despliegas una app en AWS, tú eres el "servidor web" del diagrama de abajo. Entender el journey completo te ayuda a debuggear problemas reales.

1. Tu navegador — Primero revisa si ya conoce la IP de github.com (caché local). Si no, pregunta al DNS.

2. DNS lookup — El DNS es la "guía telefónica de internet". Traduce github.com → 140.82.121.4 (una IP real).

3. TCP handshake — Tu navegador y el servidor "se saludan" para establecer una conexión segura (SYN → SYN-ACK → ACK). Con HTTPS hay un paso adicional de cifrado (TLS).

4. Servidor responde — El servidor recibe tu petición HTTP GET, procesa, y devuelve el HTML/CSS/JS.

5. Navegador renderiza — El navegador convierte el código recibido en la página visual que ves.
¿Dónde entra AWS? GitHub corre sus servidores en la nube. Cuando llegas al paso 4, estás hablando con una instancia EC2, una función Lambda, o un contenedor corriendo en algún datacenter de Amazon.
3 Anatomía de una URL

Una URL no es solo un "link". Cada parte tiene una función específica. Analicemos esta:

https://tienda.ejemplo.com:443/productos/laptops?marca=dell&precio=max#resultados
https:// Protocolo — define cómo se comunican. HTTP = sin cifrar, HTTPS = con TLS cifrado.
tienda.ejemplo.com Dominio — nombre del sitio. El DNS lo convierte a una IP.
:443 Puerto — "puerta" de entrada. 443 = HTTPS por defecto (no suele verse). 80 = HTTP.
/productos/laptops Ruta — qué recurso específico pides dentro del servidor.
?marca=dell&precio=max Parámetros — filtros o datos extra enviados al servidor.
#resultados Fragmento — sección dentro de la página. El servidor no lo procesa, es solo para el navegador.
Tip práctico: En AWS, cuando configuras un Application Load Balancer, defines reglas basadas en la ruta (/api/* → backend, /static/* → S3). Entender URLs te permite configurar esto correctamente.
4 El ecosistema digital: cómo se conecta todo

Cada tecnología en el stack tiene su rol. En el curso vas a tocar casi todas estas capas:

Frontend
Lo que el usuario ve en el navegador.
HTML · CSS · JavaScript
Backend
Lógica y datos. Procesa tus peticiones.
APIs · Bases de datos · Servidores
Redes
Las carreteras que conectan todo.
TCP/IP · DNS · HTTP · VPC
Seguridad
Protege datos y accesos.
TLS · Firewall · IAM · VPN
Cloud
Infraestructura como servicio.
EC2 · S3 · Lambda · RDS
La conexión: Cuando en este curso veamos VPC (red virtual privada en AWS), estarás configurando las "carreteras" del diagrama de arriba, pero en la nube. El módulo de redes (Módulo 1) profundiza exactamente en eso.
